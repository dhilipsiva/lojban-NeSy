## Open — release track (GitHub + crates.io)

**Status:** **R0–R3 landed 2026-08-03** (see the Baseline table). The release track is closed: cutting a release is `just release-prep X.Y.Z` → review → commit → tag, and `release.yml` does the rest. **One owner prerequisite remains before the first automated tag:** add the `CARGO_REGISTRY_TOKEN` repo secret (scope `publish-update`, with an expiry) — v0.1.0 published from a local `cargo login`, and the workflow fails loudly without the secret. Operator runbook: [RELEASING.md](RELEASING.md).

### Every release (checklist — now mechanized; RELEASING.md is the runbook)

1. `just release-prep X.Y.Z`, review the diff, `just ci-all`, commit, push main.  
2. Tag `vX.Y.Z` and push it — the rest is `release.yml`.  
3. Rehearse first if anything about the release path changed (Actions → Release → Run workflow; always a dry run).  
4. Spot-check docs.rs a few hours later; refresh this status paragraph.  

Two rules the automation cannot enforce: **never re-cut a tag after any
successful publish** (bump the patch instead), and **"Re-run failed jobs" uses
the workflow file from that run's commit**, so a workflow fix needs a new tag.

### Release out of scope

- Manuscript / AVA materials in any release asset.
- crates.io for ui/wasm/playground (site only).
- Equating crate semver with the WIT ABI version (`nibli:engine@0.7.0` today) — the two move independently.
